# План: интерфейс Kibborg CLI по образцу Grok CLI

План зафиксирован по живым фактам: установленный Grok CLI 1.0.30 (документация `~/.grok/docs/user-guide/*.md` и кадры в PTY), а также поведение установленных Codex, Claude Code и OpenCode. Инструменты съёмки кадров — `Kibborg_CLI/tests/ref-probe.mjs` (сырой PTY-вывод и терминальные режимы) и `Kibborg_CLI/tests/ref-render.mjs` (кадр из потока).

## Основание: что делают четыре CLI

| CLI | Перехват мыши | Альтернативный экран | Bracketed paste | Sync output |
|---|---|---|---|---|
| Grok | **нет** | нет | да | да |
| Codex | **нет** | нет | да | да |
| Claude Code | **нет** | нет | да | нет |
| OpenCode | **нет** | нет | да | да (+ truecolor, DEC 2027) |

Вывод: ни один не забирает мышь, поэтому выделение, копирование и колесо у них делает терминал. Kibborg включал `1000h/1002h/1006h` и повторял эти жесты сам — отсюда сломанный скролл, выделение и копирование.

## Порядок и правила

1. Этапы идут по номерам: каждый следующий опирается на предыдущий.
2. Внутри этапа сначала меняется рендер (tui), затем поведение (client-node), затем тесты.
3. Этап закрыт, когда: тесты зелёные, `oxlint` чистый, есть живой кадр, README/CHANGELOG обновлены.
4. Ничего из `vendor/` и ядра не меняется без отдельной причины, зафиксированной в описании коммита.
