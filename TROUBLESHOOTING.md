# TROUBLESHOOTING — Kibborg CLI

Формат раздела: симптом → причина → действие. Если действие не помогло — соберите диагностику из последнего раздела.

## Нет TTY (пайп, CI, перенаправленный вывод)

Симптом: `kibborg` печатает построчный вывод, интерактивный интерфейс не открывается.
Причина: CLI определяет отсутствие терминала и переходит в plain-режим — это штатное поведение, а не сбой.
Действие: используйте headless-форму (`kibborg -p "..." --output-format json`) и флаги принятия решений (`--permission-mode`, `--auto`, `--yolo`, `--question-answers <file.json>`).

## Команда завершилась кодом 3

Симптом: ход остановлен, в stderr сообщение о необходимости интерактивного решения.
Причина: в headless-режиме агент дошёл до approval или вопроса модели, а отвечать некому (политика `--fail-on-question` по умолчанию).
Действие: либо передайте решения заранее (`--question-answers <file.json>`), либо выберите режим (`--permission-mode workspace-write`, `--auto`), либо запускайте интерактивно.

## Нет ключа провайдера

Симптом: код выхода 2, сообщение об отсутствии учетных данных.
Причина: не задан `DEEPSEEK_API_KEY` и в managed-хранилище нет записи.
Действие: `kibborg auth` для настройки из терминала, либо задайте переменную окружения, либо проверьте `$DSH_HOME/.credentials.yaml`.

## Профиль отсутствует или устарел

Симптом: сообщение о расхождении `dsh.profile.bundles` либо об отсутствии профиля `kibborg`.
Причина: профиль не создан, или его список бандлов не совпадает с ожидаемым (`@deepseek-ai/dsh-base`, `@kibborg/cli-bundle`).
Действие: `kibborg doctor` (только покажет причину), затем `kibborg doctor --fix` (исправит и напечатает, что изменено). Тихих автоматических починок в CLI нет.

## Нет собранных артефактов ядра

Симптом: ошибка импорта клиентских Remote-артефактов; в логе упоминаются `typert.remote-client.*`.
Причина: не выполнен полный билд ядра; строгие Remote-дескрипторы генерируются сборкой.
Действие: из корня монорепо `pnpm run build` (при необходимости сначала `pnpm run build:lib:host`, затем `pnpm run build:lib:client`), затем повторите запуск.

## Клиентский слой не запускается в Node

Симптом: ошибка вида «window is not defined», «document is not defined» либо отказ монтирования клиентского плагина.
Причина: часть клиентских плагинов объявлена с `dsh.client.platform: web`; не все из них безопасны для исполнения в Node.
Действие: это известный риск K0.0. Зафиксируйте список модулей, обращающихся к DOM, и исход spike (a/b/c) по шаблону из `PLAN.md` §6. Решение между тонким слоем и аддитивным экспортом принимается по этому списку, а не по догадкам.

## Разрыв соединения в режиме attach

Симптом: сообщение о смене поколения соединения, интерфейс приостановил обновления.
Причина: поток `events.mux` либо `events.host` закрылся; клиент переходит в переподключение.
Действие: дождитесь восстановления — клиент повторно забирает baselines (сессии, workspace, проекции, очередь) и продолжает сессию; лог не теряется. Если сервер остановлен — запустите его снова и выполните `kibborg attach <url>`.

## Прерывание на середине хода

Симптом: после Ctrl+C ход остановлен, инструмент прерван.
Причина: первый Ctrl+C или Esc отменяет активный ход (`session.cancel`), второй в течение ~800 мс завершает процесс.
Действие: если прервали запись инструмента — проверьте изменённые файлы (`git status`, список diff в сессии). Незавершённые узлы закрываются как cancelled, лог остаётся консистентным.

## Вторая инстанция не может открыть ту же сессию

Симптом: сообщение о занятом потоке либо предложение подключиться.
Причина: поток событий сессии принадлежит одному потребителю.
Действие: используйте `kibborg attach <url>` к работающему процессу либо создайте новую сессию.

## Windows-терминал: артефакты вывода, копирование, ресайз

Симптом: разъезжающаяся рамка, нечитаемые символы, не работает вставка из буфера или LCtrl-комбинации.
Причина: особенности Windows Terminal/ConPTY — отсутствие SIGTERM-семантики, поведение alt-screen и системного буфера.
Действие: используйте режим `inline` (по умолчанию), при проблемах — `--no-alt-screen` или аварийный plain-режим (`KIBBORG_PLAIN=1`); проверьте кодировку консоли UTF-8; копирование последнего ответа доступно командой `/copy` (OSC 52).

## Секрет попал в командную строку

Симптом: предупреждение о токене в argv.
Причина: токен передан аргументом (`--token ...`) и видим в списке процессов.
Действие: передавайте токен через переменную окружения `KIBBORG_TOKEN` или файл; снимите значение из истории оболочки; при аудите учтите возможную утечку и перевыпустите токен.

## Сервер не стартует при bind вне loopback

Симптом: отказ запуска `kibborg serve` с сообщением о токене.
Причина: политика безопасности запрещает слушать внешние интерфейсы без аутентификации.
Действие: задайте `KIBBORG_TOKEN` (или файл токена) либо запускайтесь на `127.0.0.1`. CORS по умолчанию выключен — расширяйте осознанно и отдельно.

## Диагностика: что собрать перед обращением

1. `kibborg doctor --json` — полный отчёт (секреты маскируются; для раскрытия значений нужен явный `--reveal`).
2. Версии окружения: `node -v`, `pnpm -v`.
3. Путь профиля и его `package.json` (поле `dsh.profile.bundles`).
4. Наличие артефактов сборки (`lib/typert.remote-client.*` в пакетах ядра).
5. Команда, её полный вывод (stdout и stderr) и код выхода.
